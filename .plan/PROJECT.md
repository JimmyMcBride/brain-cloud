# Project: brain-cloud

Created: 2026-07-27T17:43:26Z

## Vision

Brain Cloud is the hosted and self-hostable platform for Brain Core and optional official/community modules. It gives people, teams, and agents durable context, memory, retrieval, collaboration, and workflow capabilities through one public protocol.

## Principles

- Local, cloud-native, hybrid, hosted, and self-hosted operation remain first-class.
- Brain Core works without optional modules.
- Planning is the first major optional official Brain module, not a separate cloud platform.
- Official modules receive no private internal exceptions.
- Community modules eventually use an external process model.
- Hive Mind remains core; modules cannot bypass permissions, scope, or provenance.
- One Brain Cloud web application and one SDK family per language expose enabled capabilities.
- Data remains portable and durable writes remain auditable.

## Constraints

- The primary repository family is `brain`, `brain-cloud`, and `brain-cloud-sdk-go`.
- Do not implement Plan Cloud, a separate Plan frontend/SDK/identity system/agent gateway, or official Linear integration.
- The standalone `plan` repository remains during migration.
- GitHub source mode is temporary coordination for this repository, not Planning's permanent backend architecture.
- The Planning domain and migration require a separate approved integration contract.
- Do not add arbitrary in-process third-party code or external module execution before supervised official OTP applications validate contracts.
- `.plan/.meta/linear.json` is required legacy metadata generated by the current Plan CLI. Its values are inactive because `.plan/.meta/workspace.json` sets source mode to `github`; it is retained only for workspace-schema compatibility and is not product direction.

## Planning rules

- Specs remain the canonical execution contract.
- Brainstorms are discovery material; refine and challenge before promotion.
- In current GitHub source mode, Plan owns planning artifacts. Never bypass it with raw `gh` issue/project commands.
- Historical artifacts may preserve superseded context only when clearly marked.
- Each phase stays bounded by explicit acceptance criteria and exclusions.

## Current focus

Phase 1, Phase 2A, and Phase 2B are complete. GitHub spec [#9](https://github.com/JimmyMcBride/brain-cloud/issues/9) adds owner-managed human membership lifecycle, one-time target-member credentials, final-owner safety, transactional credential revocation, and membership audit events to the Phase 2A identity and tenant foundation. Invitations, teams, agent credentials, interactive login, and fine-grained project ACLs remain later Phase 2 work. Module framework implementation begins later in Phase 10. Planning integration begins only after a dedicated contract.
